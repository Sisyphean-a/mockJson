# 响应场景条件分支

## 一句话

面向 Mock 控制台使用者、产品与界面设计人员的功能及交互设计说明，描述如何根据请求内容选择响应场景。日期：2026-10-23。

状态：功能已实现，自动化测试及桌面、窄屏交互检查通过；持久化与共享判定改动的独立审查待完成。以用户已认可的有序分支方案为基线；未命中行为采用用户最终确认：**开启兜底返回指定场景，关闭兜底放行真实请求。**

## 这是做什么的

当前一个接口最多启用一个响应场景，每次请求都返回该场景。本次保留这种固定响应方式，新增「条件分支」方式：同一个接口根据请求头或请求体内容，自动选择不同的完整响应场景。

工作流：**选择接口 → 配置条件与场景的对应关系 → 试算请求 → 保存生效 → 请求得到匹配场景，或执行未命中动作。**

场景负责「返回什么」，分支负责「什么请求返回它」。不把场景复制到分支里，不把界面做成通用流程编排器。

## 做完之后，你会看到什么

### 1. 模式入口与原有能力

左侧顶部同一行放置 **固定响应 / 条件分支** 分段选择和「＋ 新建」，不再单独显示「响应场景」标题。模式属于当前接口，不影响其他接口。

- 固定响应保留现有行为：点击场景只切换查看对象，独立开关启用或停用响应，一个接口最多启用一个场景。
- 条件分支隐藏所有场景行的启用开关与「当前启用」标记，右侧默认展示分支规则。
- 接口自身的启用开关保持独立；关闭接口后，分支和兜底都不接管请求。
- 原有场景名称、颜色、完整 JSON 响应、HTTP 状态、延迟、编辑、复制和排序能力保留。
- 旧配置继续以固定响应方式工作，不因增加功能而自动改变响应。

### 2. 左侧管理场景，右侧管理分支

左侧在场景列表上方增加「分支规则」入口，并显示分支数量。场景行按用途显示「被引用」「兜底」等标记；同一场景可以同时被多个分支引用，也可以兼任兜底。

右侧使用纵向有序分支列表，顶部显示「从上到下判断，首个命中生效」，并提供「试算请求」「保存」。说明只出现一次。

以下为布局示意，名称和条件仅用于说明，不是预置业务数据：

```text
[ 固定响应 | 条件分支 ]  ＋ 新建 │ 条件分支             试算请求  保存
                                │ 从上到下，首个命中生效
                                │
⑂ 分支规则                 2 条 │   ┌─ 1  指定空白响应
────────────────────────────────│   │   请求头场景标记 = 空白 → 空白场景
默认场景                   兜底 │   │
空白场景                 被引用 │   ├─ 2  已有身份证
有身份证                 被引用 │   │   请求体身份状态 = 已认证 → 有身份证
                                │   │
                                │   ├─ ＋ 添加分支
                                │   └─ 未命中时  [兜底开启] → 默认场景
```

- 每个分支收起时保留两行：第一行是顺序、名称和操作，第二行合并条件摘要与目标场景。展开后直接在标题栏编辑名称，条件按行对齐，列名只出现一次，类型与比较值放在同一组控件；字段写法按需展开，不在每条条件下重复解释。
- 点击左侧场景，右侧回到现有响应编辑区；顶部提供「← 分支规则」。
- 点击分支中的目标场景或「查看」，进入响应编辑区；返回后恢复此前的分支位置与编辑上下文。
- 查看或编辑某个场景不会改变当前响应模式，也不会将该场景隐式设为固定响应。
- 场景排序只改变场景列表顺序，不改变分支判断顺序。

### 3. 创建和编辑分支

每条分支包含：名称、条件组合方式、一条或多条条件、一个目标响应场景。新分支默认「任一条件」，新条件默认「JSON 请求体」；已有配置不受影响。

条件编辑按「来源 → 字段 → 判断方式 → 比较值」展开：

- 来源支持请求头、JSON 请求体。
- 请求头填写头名称；名称不区分大小写，值按所选条件比较。
- 请求体选择或填写字段位置，支持定位嵌套字段；不要求用户编写判断代码。
- 同一分支可选择「全部条件」或「任一条件」，默认不提供多层嵌套。
- 提供等于、不等于、包含、存在、不存在；数字值提供大小比较。只展示适用于当前值类型的判断方式。
- 文本、数字、布尔值和空值明确区分，不把数字与数字文本视为同一值。
- 「存在 / 不存在」不显示比较值输入框；字段值为空不等同于字段不存在。
- 字段不存在时，普通比较不命中，包括「不等于」；需要判断缺失时使用「不存在」。
- 请求体不是有效 JSON 或无法取得时，请求体条件不命中，不能把「无法读取」误判成「字段不存在」；请求头条件仍正常判断。
- 条件组合按实际结果计算：全部条件需要全部成立，任一条件只需一条成立。
- 不允许保存没有条件或没有目标场景的分支；不设置条件的统一响应由底部兜底承担。

分支可以添加、修改、删除和调整顺序。支持拖动，也提供「上移 / 下移」，不把拖动作为唯一方式。删除操作应清楚标明当前分支，不能连带删除目标场景。

选择目标场景时可直接「＋ 新建场景」；创建成功后选为当前分支的目标，返回继续编辑。左侧「＋ 新建」仍可独立创建场景，不自动新增分支。

### 4. 判断顺序与兜底

请求先按原有接口匹配规则确定适用接口，再按该接口的响应模式处理。条件分支不是替代接口匹配规则，也不是跨接口的全局条件。

在条件分支模式下：

1. 从第一条分支开始判断，首个命中后返回其目标场景，不再执行后续分支。
2. 多条分支可能同时满足时，顺序就是优先级，不随机选择、不合并响应。
3. 所有分支都未命中时，执行底部固定位置的「未命中任何分支」配置。
4. 开启「兜底响应」时必须选择一个场景，未命中就返回它；常规宽度下，未命中动作、兜底开关与场景选择同行展示。
5. 关闭「兜底响应」时，显示「放行真实请求」，不再显示一个看似仍会生效的场景选择；重新开启时保留此前选择，供用户确认。
6. 关闭兜底不影响正常命中的分支。零条分支时，同样执行未命中动作。
7. 接口已匹配、但其分支未命中且关闭兜底时，结果就是放行真实请求，不偷偷改用其他场景或其他接口的 Mock。

「放行真实请求」沿用当前接入方式：

- **Chrome 扩展**：浏览器继续发出原始真实请求，不依赖控制台中的真实服务环境。
- **Reqable / 本地代理**：转发到当前测试包选择的真实服务；没有配置真实服务时，明确报告配置错误，不伪装成成功或返回任意场景。

分支判断不能导致放行后的请求体丢失、被修改或重复发送。上传文件、二进制等当前不采集内容的请求，不新增文件内容判断能力；可用的请求头条件仍可使用。

### 5. 模式切换、保存与配置保护

- 首次查看条件分支时，以当前启用场景预填兜底；没有启用场景时不擅自指定其他场景，呈现当前未命中动作供用户配置。仅查看预填配置不标记未保存。
- 「固定响应 / 条件分支」分段只切换工作区，两边草稿和编辑位置保留，不弹确认框，也不改变真实请求行为。
- 明确区分「当前生效模式」与「正在查看的模式」。聚焦控件或切换工作区不算修改，只有实际改动才显示「有未保存修改」。
- 查看未启用的模式时，提供「启用固定响应」或「启用条件分支」；已有实际改动时显示「保存并启用」。明确点击后才应用该模式及配置；当前生效模式内的修改继续通过「保存」生效。失败或保存完成前，真实请求仍使用原配置。
- 固定响应工作区展示上次固定选择，允许修改或停用；查看不等于恢复固定响应。切换工作区不清空另一边的配置，关闭兜底也不删除场景。
- 仅在切换接口或离开当前编辑会丢失真实未保存修改时，提供保存、放弃、取消。
- 保存中显示进度并避免重复提交；成功才显示已生效。失败保留草稿、说明失败并允许重试，原生效配置保持不变。
- 场景 JSON 编辑沿用现有保存方式；分支中的保存只负责模式与选择逻辑，不让用户误以为场景内容也必须等待这次保存。
- 删除被分支或兜底引用的场景时，列出引用位置，要求先解除或替换引用，不允许保存悬空引用，也不静默改为放行。

### 6. 试算请求

在分支工作区右上角提供「试算请求」。按需打开试算区，输入请求头和请求体；不常驻挤占规则编辑区域。

- 使用当前查看模式的配置计算；存在未保存修改，或该模式尚未启用时，明确标记「草稿试算」。
- 只试算当前接口的场景选择，不代替跨接口匹配测试。
- 显示每条已判断分支的命中或未命中结果，以及相关字段实际值、预期值或缺失原因。
- 首条命中后的分支标为「未执行」，不能显示成「未命中」。
- 结果明确显示三种之一：命中某分支及场景、返回兜底场景、放行真实请求。
- 请求体无效、不可读取和字段不存在分别说明；不会用空对象掩盖解析问题。
- 修改规则、顺序、兜底或试算输入后，旧结果标记「已过期」，重新试算后更新。
- 试算不发送真实请求、不调用真实服务、不触发业务副作用；即使结果为放行，也只展示决定。
- 试算结果不承诺真实服务最终返回什么；代理未配置真实服务时应提示该限制。

### 7. 状态与视觉规范

沿用现有浅色工作台、蓝色强调、场景颜色、JSON 编辑器和左右布局，不换品牌、不新增装饰性图像。

视觉重心是「条件 → 目标场景」；左侧负责定位与切换，右侧负责判断与编辑。默认只展开正在编辑的分支，其他分支以紧凑摘要提供扫描依据。

- 桌面左侧约 300–340px，右侧随可用宽度伸展；常规文字约 14px，区域标题约 16px，字段位置和值使用等宽字体。
- 用细边框、轻背景、稳定间距和窄连接线表达顺序，不使用大阴影卡片、自由拖线、缩放画布。
- 蓝色用于选中与关键操作，错误使用明确文字和错误色；命中、未命中、兜底和未保存都不能只靠颜色表达。
- 按钮与可交互行有悬停、按下和清晰的键盘焦点状态；禁用操作说明原因，排序可用键盘替代。
- 空列表直接显示「添加分支」与未命中配置，不填充假数据；没有场景时提供新建入口。关闭兜底且没有分支可明确保存为放行，开启兜底但没有目标场景不能保存。
- 输入错误贴近对应字段，保留原输入并说明修改办法；保存失败反馈贴近保存按钮。
- 分支较多时靠摘要、顺序与滚动扫描，不强制横向找连线；长场景名称不挤坏按钮，提供完整名称查看方式。
- 窄屏将场景列表收为选择入口，条件字段纵向排列；试算改为独立全宽视图，保留返回位置与草稿。
- 每条解释只在最相关的位置出现一次，不在外层与分支内部重复写教程。避免为了填满空白增加说明。

## 走一遍典型场景

### 按请求内容选择响应

1. 用户打开一个已有默认场景、空白场景、有身份证场景的接口。
2. 切换到条件分支，默认场景预填为兜底，当前线上行为暂不改变。
3. 第一条分支判断请求头中的场景标记是否要求空白结果，目标为空白场景。
4. 第二条分支判断请求体中的身份状态是否已认证，目标为有身份证场景。
5. 用同时满足两条分支的请求试算：第一条命中，返回空白场景，第二条未执行。
6. 调整两条分支顺序，旧试算结果过期；重新试算后返回有身份证场景。
7. 保存成功，之后请求按新顺序返回响应。

### 没有命中时

| 分支结果 | 兜底状态 | 用户得到的结果 |
| --- | --- | --- |
| 某条命中 | 开或关 | 返回首条命中分支的场景 |
| 全部未命中 | 开启并指定场景 | 返回指定兜底场景 |
| 全部未命中 | 关闭 | 扩展由浏览器放行；代理转发真实服务 |
| 全部未命中 | 关闭，代理未配置真实服务 | 明确配置错误，不返回假成功 |
| 零条分支 | 开启并指定场景 | 返回兜底场景 |
| 零条分支 | 关闭 | 放行真实请求，受接入方式约束 |

### 错误与恢复

- 请求体不是有效 JSON：请求体条件不命中，请求头条件仍可命中；最终仍遵循兜底或放行决定。
- 删除正在使用的场景：提示哪些分支或兜底引用它，处理引用后才能删除。
- 保存失败：草稿保留，实际请求继续使用原配置，用户可重试。
- 切回固定响应再切回来：已保存分支与兜底仍在，不必重新创建。

## 明确不做

- 不做自由连线画布、任意嵌套逻辑、脚本条件或通用工作流。
- 不做响应合并、场景串行执行、轮询、随机返回或按次数返回。
- 不扩大接口本身的匹配条件范围；本次请求体判断用于已匹配接口内部的响应选择。
- 不分析上传文件内容，不承诺判断当前接入方式无法读取的请求头或请求体。
- 不新增全局流量看板，不重新设计现有 JSON 编辑器、测试包或真实服务管理。
- 不通过试算发起真实请求，不把尚未实现的设计描述成现有能力。

## 名词约定

- **固定响应**：由用户启用一个场景，该接口的匹配请求统一使用它。
- **条件分支**：按顺序判断请求内容，首条命中的分支决定响应场景。
- **响应场景**：一份完整响应，包含 JSON 内容、HTTP 状态和延迟，可被重复引用。
- **兜底场景**：所有分支都未命中且兜底开启时返回的指定场景，不等于名称恰好叫「默认场景」的场景。
- **放行真实请求**：不返回 Mock，按照扩展或代理各自原有方式访问真实服务。
- **试算**：仅说明给定请求会选择哪个响应或是否放行，不实际执行请求。
