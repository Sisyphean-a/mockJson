# Mock Console

本地 Mock / Proxy 控制台：用逻辑接口、匹配条件和响应场景，快速切换不同请求的返回结果。

仓库现在包含两个产品 npm workspace 和一个共享契约 workspace：

- `packages/mock-console`：Fastify Mock / Proxy 服务和 Vue 管理页面，拥有 Mock 配置、匹配和运行日志。
- `packages/chrome-extension`：Chrome Manifest V3 扩展，不保存 Mock 配置，只负责页面请求桥接。
- `packages/extension-contract`：扩展与本机服务共用的 resolver、响应交接、接口快捷操作 TypeScript 线协议类型，以及无 IO 的 JSON 字段组合函数。

## 启动 Mock Console

```bash
npm install
npm run dev
```

管理页面（开发模式）默认在 `http://127.0.0.1:22334`，Mock / Proxy 服务监听 `0.0.0.0:22333`。管理 API 只允许本机访问，局域网设备仍可访问 Mock / Proxy 路径。配置默认保存在当前用户数据目录：Windows 为 `%LOCALAPPDATA%\mock-console\state.json`，macOS 为 `~/Library/Application Support/mock-console/state.json`，Linux 为 `$XDG_DATA_HOME/mock-console/state.json` 或 `~/.local/share/mock-console/state.json`。也可以通过 `MOCK_STATE_FILE` 指定路径。

仓库中的 `data/mock-data.example.json` 只是脱敏示例，不会自动加载。写入采用串行临时文件替换并保留有效 `.bak`；主文件损坏时自动恢复备份，两者都损坏时服务会明确报错。

正式使用时执行：

```bash
npm run build
npm start
```

此时页面、管理 API 和 Mock 请求统一使用 `http://127.0.0.1:22333`。终端默认只输出启动、错误和安全拒绝信息，不再逐条输出请求的 `incoming request` / `request completed`；Proxy 和 Chrome 扩展判定结果请在控制台日志面板查看，日志可按来源区分 `Proxy / Reqable` 与 `Chrome 扩展`。Package 内可配置多个真实服务环境，当前选中的环境是 Reqable / 本地 Proxy 未命中或执行混合场景时的真实请求目标，不默认占用本地 Mock 端口。

## 使用 Mock Console

1. 启动服务并打开 `http://127.0.0.1:22333`。
2. 首次启动为空白状态，点击「+ 包」创建测试包。
3. 在顶部「真实服务」点击「配置」，新增真实服务并填写名称和基础地址，例如「测试环境」与 `https://api.test.example.com`；再新增「生产环境」等其他地址。下拉框切换当前环境后，Reqable / 本地 Proxy 未命中 Mock 或关闭 Mock 时就会转发到该环境。
4. 创建逻辑接口，添加任意 Header、URL.path 或 HTTP Method 匹配条件；新接口默认启用，匹配方式默认是满足任一（OR），已有条件可在操作列直接编辑或删除。接口列表可通过左侧拖拽手柄长按排序，搜索时暂不允许排序。
5. 创建场景，选择响应类型并设置 JSON、状态码和延迟；接口没有场景时，首个新场景默认启用，后续新场景默认不启用；使用场景旁的开关启用、停用或快速切换当前返回。场景列表也支持拖拽排序，顺序会保存到当前接口。
6. Reqable 将需要 Mock 的请求重写到 `http://电脑局域网IP:22333/原始路径`，保留查询参数和业务 Header。
7. 顶部「请求日志」进入独立的全宽观测视图；点击日志行查看详情，命中接口可在详情中通过「查看接口配置」返回对应接口。

如果 Reqable / 本地 Proxy 请求没有命中接口：

- 已配置并选中真实服务：Mock Console 向该环境转发并返回真实响应。
- 没有选中的真实服务：返回错误，因为原始响应仍在真实服务或 Reqable 中，本项目无法直接获得它。
- 只希望 Reqable 自己处理未命中请求：不要把这些请求重写到 `22333`。

HTTPS 请求由 Reqable 负责解密和重写；本项目不提供 HTTPS MITM。Android 连接电脑时使用电脑局域网 IP，不要使用 Android 自己的 `127.0.0.1`。

### 三种响应场景类型

新建或编辑响应场景时选择「响应类型」，不改变固定响应/条件分支的选择方式；旧场景仍按完整 Mock 执行。

| 类型 | 响应来源 | 字段配置 |
| --- | --- | --- |
| 完整 Mock | 直接返回场景 JSON，不请求真实接口 | 不需要 |
| 真实响应 + 字段 Mock | 以本次真实 JSON 为底，覆盖选中字段 | 填需要 Mock 的路径；场景 JSON 提供对应值 |
| Mock 响应 + 真实字段 | 以场景 JSON 为底，仅更新选中字段 | 填需要真实值的路径 |

例如图片 URL 会过期：选择「Mock 响应 + 真实字段」，填写 `/data/imageUrl`，JSON 中填写其余需要 Mock 的内容（如 `{ "data": { "name": "测试用户" } }`）。下次请求时只把 `data.imageUrl` 换成本次真实接口的最新值。新建场景时，在侧栏设置名称、类型和字段，在 JSON 编辑器填写初始响应；后续仍在工作区编辑 JSON。场景「编辑」只保存名称、类型与字段等设置，状态码、延迟和标记颜色位于「更多设置」。

- 每行一个 JSON Pointer，例如 `/data/imageUrl`；两份数据使用相同路径。父级必须存在，允许新增对象末级字段；数组使用已存在的明确下标（如 `/items/0/url`），不自动按 ID 对齐。路径不能重复或父子重叠。
- **混合场景会真实调用一次接口，提交类接口也会产生真实操作。** Proxy 使用顶部当前真实服务环境；扩展复用浏览器原始 URL、登录态、请求体和凭证设置，不使用该环境。
- 真实请求必须返回成功（2xx）的可读 JSON。网络、HTTP、JSON 或字段错误只让该请求失败：Proxy 返回 502，fetch 拒绝，XHR 触发 error；不重试、不返回旧 Mock，其他完整 Mock 不受影响。
- 最终状态码使用场景配置（200–599，排除 204/205/304），延迟在真实响应后追加。不支持 HEAD、流式或二进制响应组合；需要读取完整 JSON，不是流式转发，大响应会增加内存与等待时间。
- 扩展服务端日志只显示混合判定（没有最终响应）；最终组合结果和错误在扩展接口面板查看。

更新后重启 Mock Console，在 `chrome://extensions` 重新加载扩展，并刷新业务页面，确保三方协议同步。

## 使用 Chrome 扩展

构建扩展：

```bash
npm run build:extension
```

然后在 Chrome 打开 `chrome://extensions`，开启「开发者模式」，选择「加载已解压的扩展程序」，目录选择：

```text
packages/chrome-extension/dist
```

点击浏览器工具栏中的扩展图标可以打开 Popup：

- **页面域名白名单**：默认是 `localhost` 和 `127.0.0.1`；可按每行一个页面域名配置，例如 `app.example.com`，并同时匹配其子域名，不区分端口。页面默认不包装 `fetch` 或 XHR，也不发送 Mock 判定请求；留空时所有页面都保持原生请求 API，但仍可单页开启“记录本页请求”。iframe 按自身页面域名独立判断。
- **全局 Mock**：暂停或恢复白名单页面的 Mock。
- **当前标签页**：只暂停或恢复当前白名单标签页的 Mock；非白名单页面显示“不在页面白名单”，不能通过开关绕过白名单。
- **记录本页请求**：对当前 http(s) 标签页显式开启只记录模式（包括非白名单页面）；只观测 `fetch` / 异步 XHR，不询问 Mock Console、不改写请求。白名单页面开启 Mock 时自动记录，无需单独打开。
- **打开请求面板**：在 DevTools 顶部打开「接口面板」，或在新标签页中独立打开；两者展示同一份当前标签页请求数据。
- **连接状态**：显示 Mock Console 是否在线，以及是否已有当前 Package。

白名单保存在扩展的本地配置中；已有域名值继续保留，但现在代表页面域名，如果之前填写的是 API 域名，需要改为实际打开的网页域名。全局开关和当前标签页开关只保存在扩展的临时会话状态中。扩展不会保存 Mock 规则或场景。切换白名单后，已打开的页面会立即刷新拦截状态；切换开关后重新发起请求即可生效，已经发出的请求不会被中途改变。

扩展默认连接本机 `http://127.0.0.1:22333`。页面域名命中白名单且 Mock 开关启用时，扩展才包装该页面的 `fetch` 和异步 `XMLHttpRequest`，把 URL、Method 和页面可观察的 Header 交给 Mock Console 判定；对单个标签页显式开启“记录本页请求”时也会包装，但只观测和本地记录，不发送判定请求。请求目标域名不参与白名单过滤，白名单页面访问跨域 API 也可以进入判定；multipart / FormData 上传也能 Mock JSON 返回，不支持的请求仍原生放行：

- 命中启用接口和当前场景：完整 Mock 直接返回场景 JSON；混合类型发出一次原生请求，再按指定字段组合（见上方三种响应场景类型）。
- **上传接口**：照常用路径与 Method 等规则匹配，无需新开关。fetch multipart 或异步 XHR FormData / multipart 只发送 URL、Method 和页面可见 Header，不读取或传输文件；完整 Mock 命中时直接返回配置的 JSON，不实际上传；混合场景需真实上传一次后组合 JSON；未命中或判定失败时保留原始请求体正常上传。日志显示“上传请求体未采集”，不支持按文件内容匹配；XHR 自动生成的 Content-Type 不保证可参与匹配。若返回图片地址供页面预览，请使用真实可访问的地址。独立 Blob / 二进制 XHR 上传及 fetch 的图片、音视频、application/octet-stream 请求仍直接放行。
- 未命中、接口未启用、Mock Console 未启动或判定超时：调用浏览器原生 API，继续真实请求。Service Worker 最多等待 1 秒，页面桥接再保留 200ms 消息往返余量；连续两次 resolver 失败后扩展短路 3 秒，并在当前扩展会话保存健康状态，后续请求立即放行，避免服务不可用时反复等待。已取消或超过 32 个并发判定的请求也直接放行。已到达 Mock Console 的扩展判定会写入请求日志并标记为 `Chrome 扩展`，白名单过滤、扩展暂停或扩展侧超时不会产生服务端日志。

扩展模式不使用 Package 的真实服务环境配置，也不保存接口、规则或场景。页面取消请求时，扩展会尽量同步取消尚未完成的本机判定；当前只覆盖页面脚本的 `fetch` / 异步 XHR，不覆盖导航、图片/脚本资源、WebSocket、Worker / Service Worker 请求、同步 XHR、流式或二进制响应。浏览器自动补充且页面不可观察的 Header（例如 Cookie）不保证可参与扩展匹配。

### 请求观测面板

两个入口共用同一份数据，不需要打开后台日志：

- **DevTools 面板**：按 F12 打开 DevTools，在顶部选择「接口面板」，与 Network 并排显示，不用切换浏览器标签页（推荐）。
- **独立页面**：Popup →「独立页打开请求面板」，适合把面板放到另一个窗口或屏幕。

面板能力：

- 列表按发起时间显示方法、URL、状态码、耗时、大小，以及该请求是 Mock、放行还是仅记录；点击行后在底部的「请求 / 响应」tab 间切换，查看请求头、文本请求体、响应头、文本响应体和错误。
- 支持搜索、按 Mock / 放行 / 只记录 / 失败筛选、暂停、清空，以及复制 URL、复制为 cURL、复制响应体；请求头和响应头直接显示原值。
- 放行请求的响应体通过 `Response.clone()` 读取，不会改变页面拿到的响应；单条请求体/响应体预览上限 64 KB，超出显示为截断。上传体（multipart / FormData）、流式（`text/event-stream`）和不透明响应不采集内容；二进制请求仍记录 URL、方法、状态和响应头，但不读取内容。
- 日常记录只保存在扩展的 `chrome.storage.session` 和 Service Worker 内存中，不自动发送到 Mock Console，不需要后端；Mock Console 离线时仍能记录放行请求。每个标签页内存保留最近 500 条，会话存储保留最近 200 条。
- 面板不覆盖静态资源、导航、Worker / Service Worker、WebSocket 和重定向中间跳，也不推断请求之间的调用因果；它定位为接口级观测面板，不承诺完整替代 DevTools Network。

### 右键快捷操作

在请求行右键，或选中请求后按 Shift+F10：

- **启用 / 停用 Mock**：只显示当前状态对应的一个操作。启用时恢复原来的固定响应或条件分支；停用时保留配置和场景，后续请求走真实接口，不继续匹配低优先级 Mock。Proxy 仍需配置当前真实服务环境。
- **切换响应场景**：选择已有场景后启用固定响应；原条件分支保留。
- **打开接口配置**：定位到控制台当前测试包内的接口；测试包变化时不会自动切换全局测试包。
- **保存此响应为新场景…**及复制 URL、cURL、响应内容。

菜单修改的是**当前测试包的全局配置**，影响所有页面和 Reqable / Proxy 的后续请求；不重放历史请求，不改变历史记录标识，也不自动开启扩展或修改白名单。浏览器是否拦截仍取决于扩展的全局/本页开关和页面白名单。已打开的控制台刷新后可看到最新配置。

多个接口匹配时先选择要修改的逻辑接口，原匹配优先级保持不变。没有配置时可将完整 JSON 响应带到控制台确认创建；不能把缺失或截断内容直接当成 Mock 场景。服务离线不影响本地观测和复制，配置操作会提示启动服务。

右键配置查询只在打开菜单时发送 URL、Method 和匹配所需 Header，不发送请求体、响应体，也不重放请求。配置变化导致菜单过期时，请点击“重新读取配置”后再操作；写入失败不会自动重试。

升级后重启 Mock Console、重新加载扩展，并重新打开接口面板和刷新控制台。旧版本不识别新增的显式放行标记，回退前请先在新版本中处理放行配置。

### 将选中的响应保存为 Mock 场景

更新后先重启 Mock Console 服务，并在 `chrome://extensions` 中重新加载扩展；已打开的 DevTools 面板也需重新打开。

1. 在接口面板选中一条请求，点击「保存为 Mock 场景」；也可点击「打开控制台」直接进入 22333 页面。
2. 控制台自动打开响应草稿，预填完整 JSON、HTTP 状态码和名称。保存到当前测试包，可新建逻辑接口，或选择已有接口追加场景；响应、名称、状态码和延迟都可修改。
3. 点击「保存场景」只保存、不改变当前响应；点击「保存并启用」会启用接口并切换固定响应，随后自动定位到新场景。目标使用条件分支时只能保存，之后在响应规则中引用该场景，不会自动切换模式。

新建接口采用 AND 联合匹配 Method、Host 和 Path，忽略查询参数；追加场景保留原匹配规则。启用场景不会改变扩展的白名单或 Mock 开关，需要按现有接入方式重新发起请求。

仅支持完整、合法的 JSON 响应及 200–599 状态码；未完成、失败、空、非 JSON 或被截断的响应不能直接保存。扩展会话恢复的预览也可能被截断，此时请重新请求后再保存。

只有主动点击交接时，选中的 URL、Method 和响应内容才发送到本机服务，不携带请求 Cookie、请求头或请求体，也不重放真实请求。草稿仅在服务内存中保留 15 分钟（过期后定时清理），重启后失效，不写入请求日志或配置；确认保存后，场景才进入正常配置持久化。

## 当前能力

- 空白初始状态，不携带参考项目的 Package 或 Mock 数据
- Package / Logical API / Scenario 完整创建、修改和删除
- 任意 Header（名称大小写不敏感）、URL 与 HTTP Method 匹配
- 优先级命中、场景即时切换、JSON/状态码/延迟校验；支持完整 Mock 和两种字段混合响应
- Package 内支持多个真实服务环境，并可在顶部下拉框切换；Reqable / 本地 Proxy 未命中或关闭 Mock 时透明转发到当前环境
- 请求日志独立全宽展示 Proxy 与 Chrome 扩展判定来源，并支持按来源和结果筛选；详情可跳转到对应逻辑接口配置
- 逻辑接口和响应场景支持长按拖拽排序，排序保存为配置数组顺序，不改变接口 `priority` 匹配规则
- Chrome 扩展对页面 `fetch` / 异步 XHR 提供独立的 Mock 判定通道，并通过 Popup 控制全局或当前标签页启停
- Chrome 扩展提供本地请求观测面板，按标签页查看接口调用顺序、请求/响应详情，不依赖后端，支持 Mock / 放行 / 只记录标识
- Vue 3 + TypeScript 页面，场景区和 JSON 编辑器为主要操作区域

Reqable 等客户端只需将请求转发至 `22333`；本项目不做 HTTPS MITM。
